# feat: Hebrew Root of the Day Website

## Enhancement Summary

**Deepened on:** 2026-02-26
**Research agents used:** TypeScript reviewer, Performance oracle, Security sentinel, Architecture strategist, Code simplicity reviewer, Frontend race conditions reviewer, Pattern recognition specialist, Claude API skill, Context7 (Next.js + Anthropic SDK), Web search (RTL, Web Audio)

### Key Improvements

1. **Claude structured outputs** — Use `zodOutputFormat()` + `client.messages.parse()` instead of prompt-based JSON. Guarantees valid, schema-compliant output via constrained decoding.
2. **On-demand ISR** — Replace time-based `revalidate = 3600` with `revalidatePath('/')` on content approval for instant freshness.
3. **Drop `@hebcal/core`** — Sefaria's `/api/calendars` endpoint already returns the current parsha. Eliminates a 174KB dependency.
4. **Security hardening** — Timing-safe auth, Zod validation on all inputs, full HTML sanitization, `NEXT_PUBLIC_` prefix guard, CORS middleware.
5. **Safer types** — Replace `correctIndex` with `correctAnswer` string, add Zod runtime schemas, derive `wordPlain` at render time.
6. **Web Audio lifecycle** — Await `resume()`, stop all nodes before new playback, disconnect nodes on `ended` event and component unmount.
7. **Simplified admin** — View + approve/regenerate only (no inline edit UI). Content editable via Upstash console if needed.
8. **Merged phases** — Phase 1+2 combined into single "Content Pipeline" phase.

### New Considerations Discovered

- Parsha names with spaces (e.g., "Lech Lecha") need slugification for Redis keys
- Sefaria text may contain HTML beyond `<big>` tags — strip all HTML defensively
- Hebrew web font with OpenType GPOS support needed for proper nikud rendering
- Trope quiz randomization must happen client-side to avoid ISR caching the same quiz
- Unicode text should be normalized to NFC before storage and comparison
- Vercel serverless timeout (10s hobby / 60s pro) may be too short for Claude generation

## Overview

A public website that helps people learn Hebrew — both modern and biblical — through a daily "shoresh (root) of the day" tied to the weekly Torah portion (parashat hashavua), plus cantillation (trope) audio matching practice. No user accounts. Content is AI-generated via Claude API with structured outputs, manually reviewed before publishing, and served from Upstash Redis.

(see brainstorm: docs/brainstorms/2026-02-26-hebrew-root-of-the-day-brainstorm.md)

## Problem Statement

Learning Hebrew roots (shorashim) is fundamental to Hebrew literacy, but existing tools are either static flashcard apps or expensive commercial products. There's no free, dynamic tool that ties daily root learning to the weekly Torah portion — a natural cadence for Jewish learners. Similarly, cantillation (trope) practice is scattered across disconnected audio recordings with no interactive exercise format. No open-source project synthesizes trope melodies programmatically.

## Proposed Solution

A Next.js App Router site deployed on Vercel with three core features:

1. **Daily Shoresh** — 1 root per weekday from the current parsha, with definition, nikud examples, and "identify the shoresh" practice problems.
2. **Shabbat Review** — Saturday shows all 5 roots from the week for reinforcement.
3. **Trope Practice** — Synthesized Ashkenazi cantillation melodies via Web Audio API, with audio matching quizzes.

Content is generated by Claude API using structured outputs (Zod schemas) from Sefaria's Torah text, staged for manual review in an admin interface, then published on schedule.

| Tailwind CSS | Styling | Rapid UI development, RTL support via `dir="rtl"` |

### Research Insights: RTL & Hebrew Text Rendering

- Set `dir="rtl" lang="he"` on all Hebrew text blocks
- Use Unicode bidi marks (LRM/RLM) for mixed Hebrew/English content to prevent reversal
- Hebrew has no capitals — increase font size by ~10% for headings and buttons vs Latin text
- Test for text truncation: Hebrew translations can be significantly longer than English
- Specify a Hebrew web font with proper OpenType GPOS tables (e.g., "Frank Ruhl Libre" from Google Fonts) for correct nikud positioning. Use `unicode-range: U+0590-U+05FF` so it only downloads for Hebrew glyphs
- Normalize all Hebrew text to NFC form before storage: `text.normalize('NFC')`

```typescript
export function isAuthorized(request: Request): boolean {
  const authHeader = request.headers.get('Authorization');
  if (!authHeader?.startsWith('Bearer ')) return false;
  const token = authHeader.slice(7);
  const expected = process.env.ADMIN_PASSWORD;
  if (!expected) return false;
  const tokenBuf = Buffer.from(token);

}
```

```typescript
let audioCtx: AudioContext | null = null;
let activeNodes: AudioNode[] = [];

function getContext(): AudioContext {
  if (!audioCtx || audioCtx.state === 'closed') {
    audioCtx = new AudioContext();
  }
  return audioCtx;
}

function cleanupActiveNodes() {
  for (const node of activeNodes) {
    try { node.disconnect(); } catch {}
  }
  activeNodes = [];
}

export async function playTrope(motif: TropeMark): Promise<void> {
  const ctx = getContext();
  if (ctx.state === 'suspended') await ctx.resume(); // MUST await before scheduling

  cleanupActiveNodes(); // Stop any in-progress playback first

  const startTime = ctx.currentTime + 0.05;
  let time = startTime;

  for (const [semitones, durMult] of motif.intervals) {
    const freq = 293.66 * Math.pow(2, semitones / 12); // D4 tonic
    const duration = 0.25 * durMult;

    const osc = new OscillatorNode(ctx, { type: 'sine', frequency: freq });
    const gain = new GainNode(ctx, { gain: 0 });

    osc.connect(gain).connect(ctx.destination);
    gain.gain.setValueAtTime(0, time);
    gain.gain.linearRampToValueAtTime(0.25, time + 0.02);
    gain.gain.setValueAtTime(0.25, time + duration - 0.05);
    gain.gain.linearRampToValueAtTime(0, time + duration);

    osc.start(time);
    osc.stop(time + duration);

    activeNodes.push(osc, gain);
    time += duration;
  }

  // Cleanup after last note ends
  const lastOsc = activeNodes[activeNodes.length - 2] as OscillatorNode;
  lastOsc.addEventListener('ended', cleanupActiveNodes);
}

export function stopAll() { cleanupActiveNodes(); }

export function suspendContext() {
  if (audioCtx && audioCtx.state === 'running') audioCtx.suspend();
}
```

## Alternative Approaches Considered

(see brainstorm: "This approach was chosen over")

| Approach | Why Rejected |
|----------|-------------|
| Astro static site with pre-generated content | Loses dynamic parsha-aware content. Would need to pre-generate all 54 weeks upfront and rebuild to update. |
| Vanilla JS + serverless | Too minimal for interactive quiz UX and audio synthesis. No component model makes it harder to scale features. |
| Pre-recorded trope audio files | Creates dependency on audio recordings, storage costs, harder to expand to new traditions. Web Audio API is more flexible. |
| User accounts for progress tracking | Adds auth complexity (database, sessions, password reset) for marginal benefit. Can be added later if needed. |
| `@hebcal/core` for parsha calendar | Adds 174KB dependency. Sefaria's `/api/calendars` endpoint provides the same data with no npm dependency. |
| Prompt-based JSON from Claude | Fragile — Claude can return malformed JSON. Structured outputs with `zodOutputFormat()` guarantee valid, schema-compliant output via constrained decoding. |
| Admin inline edit UI | Over-scoped for v1. If Claude gets content wrong, regenerate (~$0.05) or edit via Upstash web console. |

## System-Wide Impact

### Interaction Graph

- User visits page → Next.js Server Component reads from Upstash Redis (read-only token) → renders HTML → Client Components hydrate for interactivity
- Admin triggers generation → API route calls Sefaria API → passes text to Claude API (structured outputs) → validates with Zod → stores in Redis → admin reviews via read-only display → approval updates Redis status + calls `revalidatePath('/')`
- Web Audio: user clicks "Listen" → AudioContext resumes (awaited) → prior playback cancelled → new OscillatorNodes scheduled → `ended` event triggers cleanup

### Error Propagation

- **Sefaria API down:** Generation fails with error in admin UI. Published content in Redis unaffected.
- **Claude API error:** SDK auto-retries 429/5xx (2 retries with backoff). If exhausted, `GenerationError` shown in admin UI. Can retry manually.
- **Claude returns bad data:** Zod validation catches schema violations before Redis storage. Nikud validation catches missing vowel points. Both surface as warnings in admin UI.
- **Redis unavailable:** Public site serves ISR-cached page (up to 24-hour safety net). Admin routes fail gracefully.
- **Web Audio unsupported:** Trope page shows fallback message. All modern browsers support Web Audio API.

### State Lifecycle

- Content states: `draft` → `approved`. No deletion needed (old content naturally ages out or can be overwritten).
- Redis keys: `content:{slugified-parsha-name}:{YYYY-MM-DD}` — deterministic, no orphaning risk.
- Redis Set `index:drafts` tracks draft keys for efficient listing.
- No user state to manage (no accounts).

## Dependencies & Prerequisites

| Dependency | Type | Risk |
|------------|------|------|
| Sefaria API | External API (free, no auth) | Low — well-established, only needed during generation |
| Claude API (Anthropic) | External API (paid) | Low — ~$0.05/generation, once/week. Structured outputs guarantee schema compliance. |

## Risk Analysis & Mitigation

| Risk | Likelihood | Impact | Mitigation |
|------|-----------|--------|------------|
| Claude generates incorrect nikud | Medium | Medium | Structured outputs + `hasNikud()` validation + correction pass + manual review |
| Trope melodies sound unnatural | Medium | Low | Sine wave + envelope shaping; iterate on intervals |
| Double/special parsha handling | Low | Low | Combined slug key; detected via Sefaria calendar response |
| Browser autoplay blocks audio | Medium | Low | Always `await audioCtx.resume()` on user gesture |
| Admin password brute force | Low | High | Timing-safe comparison + consider rate limiting via Upstash |
| Secret env vars leaked to client | Low | Critical | Build-time `NEXT_PUBLIC_` guard in next.config.ts |
